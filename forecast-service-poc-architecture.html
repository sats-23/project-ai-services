Forecast Service — POC Architecture

Predicts future trends and outcomes from historical data, enabling better planning, resource allocation, and business decision-making. Accepts a CSV for custom model training; exposes a prediction endpoint once trained.

API Surface

POST
/v1/forecast/train

Upload a CSV and declare which columns are inputs and which to predict. Returns a job_id immediately; training runs async.

Content-Type: multipart/form-data file: <data.csv> input_cols: ["date","region","spend"] output_cols: ["revenue","demand"] version: "1.0.0" # optional
GET
/v1/forecast/train/{job_id}

Poll training status. Mirrors the existing summarize job-status pattern.

Response: { "job_id": "abc-123", "status": "completed", "model_version": "1.0.0", "trained_at": "2025-…" }
POST
/v1/forecast/predict

Run inference against a trained model. Returns a prediction per output column for each input row.

Content-Type: application/json { "job_id": "abc-123", "inputs": [ {"date":"2025-10","region":"US","spend":5000}, {"date":"2025-11","region":"US","spend":5200} ] }
GET
/v1/forecast/train

List all training jobs with pagination. Mirrors /v1/summarize/jobs listing pattern.

Response: { "pagination": { "total":12, … }, "data": [ { "job_id":"abc-123", "status":"completed", … } ] }

Rough Implementation Phases

1
Skeleton service

Scaffold services/forecast/ directory, app.py, settings.py, Containerfile. Wire up health endpoint and Swagger UI. Validate it builds and runs.

2
Data layer

Define ForecastJob ORM model. Write migration scripts. Adapt DB connection pool from summarize/db/.

3
Training pipeline

Implement POST /v1/forecast/train: accept CSV upload, validate column names, kick off background asyncio.to_thread job, persist trained model with joblib.dump, update job status in DB.

4
Inference endpoint

Implement POST /v1/forecast/predict: load model from artefact store, run model.predict(), return predictions per output column.

5
Job management endpoints

Status polling (GET /train/{job_id}), list jobs (GET /train), delete job + artefact (DELETE /train/{job_id}).

6
UI card

Carbon tile: CSV drag-and-drop, multi-select column picker, train trigger, status polling badge, predict form with results table/chart.

Key Open Decisions

DecisionOptionsRecommendation
ML algorithm scikit-learn (LinearRegression, RandomForest), Prophet, statsmodels ARIMA Start with sklearn RandomForestRegressor — no time-series requirement, easy to generalise across column types. Add Prophet as opt-in for date-indexed data.
Artefact storage Local filesystem PVC, MinIO/S3, PostgreSQL BYTEA Filesystem PVC (same pattern as summarize cache_dir); migrate to object store when multi-node needed.
Training execution asyncio.to_thread, Celery worker, separate Pod/Job asyncio.to_thread for POC (matches summarize pattern); Kubernetes Job for production scale.
DB2 live training Accept CSV only vs. DB connection string + SQL query CSV-only for POC; DB2 connector is a follow-on feature once core pipeline is proven.
